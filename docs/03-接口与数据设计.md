# 接口与数据设计

版本 0.1 · 与 `server/src/app.ts`、`server/src/db.ts` 保持一致。

## 1. 约定

- 基础地址：开发 `http://127.0.0.1:3000`，正式 `https://api.iopenai.tech`。
- 全部 JSON。出错时返回 `{ "error": "给用户看的一句话" }` 和对应的状态码。
- 需要登录的接口带请求头 `Authorization: Bearer <token>`；token 有效期 30 天，失效返回 401，小程序会自动重新静默登录并重试一次。
- 限流：每个 IP 每分钟 120 次。

## 2. 接口

### 公开

| 接口 | 说明 |
|---|---|
| `POST /auth/wx-login` | 请求体 `{code}`，返回 `{token}`。服务端用 code 向微信换 openid，没有就建用户 |
| `GET /subjects` | 科目及各自的模块：`{subjects:[{id,name,online,modules:[{id,name,glyph,intro,online}]}]}` |
| `GET /search?subject=yuwen&module=&q=&limit=5` | 见下 |
| `GET /wenyan/hot` | 出现次数最多的 12 个字 |
| `GET /wenyan/entries/:word` | 一个字的全部义项与例句 |
| `GET /wenyan/articles` | 100 篇的目录 |
| `GET /wenyan/articles/:id` | 一篇的逐句对译、加点字位置、上一篇和下一篇 |
| `GET /wenyan/topics/:type` | `tongjia` 通假字、`huoyong` 词类活用、`gujin` 古今异义、`modern` 现代文→文言 |

**搜索的返回结构**

```json
{
  "q": "遗",
  "modules": [{ "id": "wenyan", "name": "文言文", "online": true }],
  "results": [{
    "id": "wenyan", "name": "文言文", "total": 20,
    "groups": {
      "words":       [{ "word": "遗", "count": 9, "senses": 4, "summary": "赠送；丢失的东西；遗漏；遗忘、丢下" }],
      "articles":    [{ "id": 1, "title": "…", "source": "…" }],
      "modern":      { "total": 3, "items": [{ "sense_id": 1, "word": "遗", "meaning": "遗漏", "gloss": "遗漏", "offset": 9, "id": "a29-s6", "article": 29, "title": "…", "classical": "…", "modern": "…" }] },
      "classical":   { "total": 9, "items": [{ "id": "a19-s5", "article": 19, "title": "…", "classical": "…", "modern": "…" }] },
      "translation": { "total": 4, "items": [] }
    }
  }]
}
```

- `words`：字头包含关键词；关键词不超过两个字时，也匹配被关键词包含的字头。
- `modern`：义项或某处释义包含关键词，每个义项给一条例句。
- `classical` / `translation`：原文或译文包含关键词。`translation` 不重复列出原文已命中的句子。
- `limit` 控制后三组各返回多少条（默认 5，最多 50），`total` 始终是全部条数。
- 以后新增模块时，`results` 里多一个对象，各模块自己定义 `groups`。

### 需要登录

| 接口 | 说明 |
|---|---|
| `GET /me/profile` | 昵称、上次的科目、生词本数量、历史数量 |
| `PUT /me/profile` | 请求体可含 `nickname`、`avatar`、`lastSubject` |
| `GET /me/favorites` | `{words:[…], sentences:[…]}`，按加入时间倒序 |
| `POST /me/favorites` | 请求体 `{kind:"word"\|"sentence", ref}`；重复收藏不报错 |
| `DELETE /me/favorites` | 请求体同上 |
| `GET /me/favorites/check?kind=&ref=` | 是否已收藏 |
| `GET /me/history?limit=` | 搜索历史 |
| `POST /me/history` | 请求体 `{q}`；同一个词只留最新一条，最多 100 条 |
| `DELETE /me/history?id=` | 带 `id` 删一条，不带则清空 |
| `PUT /me/progress` | 请求体 `{articleId}`，记录上次读到的篇目 |
| `GET /me/recent` | 首页「继续学习」：上次读到、最近查过的 8 个词 |

## 3. 数据表

**内容（由导入脚本整体重建）**

| 表 | 内容 |
|---|---|
| `subjects`、`modules` | 科目与模块清单，`online` 控制是否上线 |
| `wy_articles` | 篇目：标题、出处、注释、加点字数 |
| `wy_sentences` | 句子：编号 `a12-s3`、原文、译文、`marks`（加点字的位置、长度、此处释义） |
| `wy_entries` | 字头与出现次数 |
| `wy_senses` | 义项：意思、词性读音、识别提示 |
| `wy_examples` | 例句：属于哪个义项、哪一句、此处译法、在句中的位置 |
| `wy_modern` | 现代文 → 文言字的对照 |
| `wy_topics` | 通假字、词类活用、古今异义三张表 |

**用户数据（导入时不动）**

| 表 | 内容 |
|---|---|
| `users` | openid、昵称、上次的科目、上次读到的篇目 |
| `favorites` | 生词本：`kind` 为 word 或 sentence，`ref` 是字或句子编号 |
| `search_history` | 搜索历史 |

文言文的表都以 `wy_` 开头。以后每个模块用自己的前缀，互不影响；生词本通过 `kind` 扩展新的收藏类型。

## 4. 数据更新流程

1. 在 `data/tools/` 里改脚本或义项表（`senses.py`），重新生成 `data/文言文字词数据.json`。
2. 在服务器上执行 `npm run import`（容器内为 `node dist/import.js`）。内容表在一个事务里清空重建，用户的生词本和历史保留。
3. 如果句子编号发生变化，指向旧编号的句子收藏会失效，所以改动对齐脚本后要检查这一点。

## 5. 与最初计划不同的地方

- 没有使用 `pg_trgm`。它在默认区域设置下对中文不起作用，而全库只有 815 句，直接用 `LIKE` 查询就足够快。
- 本地开发和测试使用内嵌数据库 PGlite（不需要安装 PostgreSQL），正式环境使用 PostgreSQL 16，两者执行同一套 SQL。
- 小程序没有引入 Pinia，登录态和缓存用一个很小的请求模块管理。
